1. Day2 里你提出的问题，逐条回答

1) 为什么 ls -h 没有显示出文件大小，而 ls -lh 显示出了文件大小？
- ls 只列出目录内容，不自动显示“人类可读格式”。
- ls -h 只是“human-readable”参数，但它通常需要和 -l 配合使用，才有意义。
- 也就是说：
  - ls -h：只会让某些输出更易读，但没有强制显示详细文件信息
  - ls -lh：相当于“详细列表 + 人类可读大小”
- 你这两个命令的区别就是：
  - ls -h：看起来更像“简短列表”
  - ls -lh：显示详细属性，包括大小、权限、时间等

2) wc 是统计文件的行数，但是 -l 参数是什么意思？
- wc 是 word count（字数/行数统计）
- 常见参数：
  - -l：统计行数
  - -w：统计单词数
  - -c：统计字节数
- 例如：
  - wc -l a.txt
  - 作用：统计 a.txt 中有多少行
- 你看到的输出：
  - 8 linux/day2-demo/a.txt
- 这表示：
  - 文件有 8 行
  - 统计对象是 “行数”，所以 -l 表示 line

3) find 中 . 是什么意思？从当前文件夹开始查找吗？
- . 表示当前目录
- 也就是：从当前目录开始递归查找
- 例如：
  - find . -name "*.txt"
- 含义：从当前目录及其子目录中查找所有名字匹配 *.txt 的文件
- -name 是名字过滤条件
- *.txt 表示通配符：
  - * 匹配任意字符
  - 所以 *.txt 就是“所有以 .txt 结尾的文件名”

4) -type是什么意思？f 又是什么意思？| head 又是什么意思？
- -type 是指定文件类型过滤
- f 表示 regular file（普通文件）
- 例如：
  - find . -type f
- 含义：只查找普通文件，不查找目录
- | 是管道符号
- 含义：把前一个命令的输出，作为后一个命令的输入
- example：
  - find . -type f | head
- 这条命令的意思是：
  - 先 find 找到所有文件
  - 再把这些文件名传给 head
  - head 默认只显示前 10 行/前 10 个结果

5) if ... fi 是什么意思？for ... do ... done 是什么意思？
- if ... then ... fi 是条件判断语法
- 结构：
  - if [ 条件 ]; then
      执行命令
    fi
- fi 是 if 的结束标记，意思是 “if 语句结束”
- 例如：
  - if [ -f "a.txt" ]; then
      echo "file exists"
    else
      echo "missing"
    fi
- 这表示：如果 a.txt 存在，就输出 file exists；否则输出 missing

- for ... do ... done 是循环语法
- 结构：
  - for i in 1 2 3; do
      echo $i
    done
- 解释：
  - i 依次等于 1、2、3
  - 每次执行 echo $i
  - done 表示循环结束
- 所以它的本质是：重复执行一段代码

6) echo 'hello' > a.txt 是覆盖原先内容写入的吗？追加内容是什么？
- > 表示重定向写入
- 它会覆盖文件原有内容
- 例如：
  - echo "hello" > a.txt
- 含义：把 hello 写进 a.txt，如果文件原来有内容，会被覆盖掉
- >> 表示追加写入
- 含义：在原文件末尾继续追加，不覆盖原内容
- 各自用法：
  - >：覆盖
  - >>：追加

7) ls | head 里，head 不加 -n 参数时默认输出前几行？
- head 默认输出前 10 行
- 不是前 4 行
- 例如：
  - ls | head
- 它会输出 ls 结果的前 10 项
- 如果你想指定数量：
  - head -n 5
- 这表示：只输出前 5 行

8) > 与 >> 的区别是什么？
- >：覆盖写入
- >>：追加写入
- 例子：
  - echo "A" > file.txt
  - echo "B" >> file.txt
- 最终 file.txt 内容：
  - A
  - B
- 如果用 > 第二次写入，会覆盖 A，得到只剩 B

9) 管道符 | 的作用是什么？
- | 是管道符
- 作用是把前一个命令的标准输出，作为后一个命令的标准输入
- 例子：
  - ls | head
  - cat files.txt | grep 'files*' | wc -l
- 这三段分别表示：
  - ls 输出的结果给 head 判断显示前几项
  - cat 输出文件内容给 grep 过滤
  - grep 过滤后的内容再给 wc -l 统计行数

10) git diff 怎么看？看不懂上面的内容
- git diff 是查看“工作区未提交改动”
- 它会比对：
  - 当前工作区
  - 暂存区/HEAD
- 你看到的内容大致是：
  - diff --git a/learn/.gitignore b/learn/.gitignore
  - --- a/learn/.gitignore
  - +++ b/learn/.gitignore
- 这表示：
  - a/learn/.gitignore 是旧版本
  - b/learn/.gitignore 是新版本
  - 下面的 + 和 - 表示新增和删除的内容
- 其中：
  - - 号：这行被删除
  - + 号：这行被新增
- 只需要看：
  - 变化前是什么
  - 变化后是什么
- 你不用看懂全部细节，先记住：
  - git diff = 看差异
  - 只看“变化对象”和“新增/删除”

11) --staged 是什么意思？为什么没有输出？
- --staged 表示查看“已暂存的内容”
- 也就是：
  - git add 之后，文件进入暂存区
  - git diff --staged 就是看暂存区和上一个提交之间的差异
- 你为什么没有输出？
  - 因为你当时还没有执行 git add
  - 也就是说暂存区是空的
- 记忆方式：
  - git diff：看工作区未暂存变化
  - git diff --staged：看暂存区变化

12) untracked、modified、staged 分别是什么意思？
- untracked：未跟踪
  - 文件存在，但从来没 add 进 Git
  - 例如新创建的文件
- modified：已跟踪文件被修改
  - 文件在 Git 管理下，但内容改过
- staged：已暂存
  - 用 git add 之后，改动进入暂存区
  - 表示准备提交

13) git diff 和 git status 的区别是什么？
- git status：看状态概述
  - 是什么文件被修改、未跟踪、已暂存
- git diff：看具体差异内容
  - 直接展示改了哪些行
- 简单理解：
  - git status = 先看“有什么状态”
  - git diff = 再看“具体差异”

14) git checkout 用于切换分支；git restore 是干什么的？
- git checkout 最早的用途：
  - 切换分支
  - 还可以用来恢复文件
- 但现在官方更推荐：
  - git restore 用来恢复文件
- 例如：
  - git restore somefile
- 作用：恢复文件到上一次提交状态
- 你之前的报错：
  - 该文件没有被 Git 跟踪
  - 所以不能 restore
- 也就是说：
  - 只有已经 tracked 的文件，才能 restore
- 另一个关键点：
  - git checkout 既能切换分支，也能恢复文件
  - 但语义比较混杂
  - 所以现在团队更常用 git switch / git restore

15) 文件覆盖与重命名含义不理解
- cp 是复制
  - 复制一个文件副本，原文件还在
  - 例如：cp a.txt backup.txt
- mv 是移动/重命名
  - 把原文件移动到新位置或改名
  - 例如：mv backup.txt renamed.txt
- 覆盖：
  - 如果目标文件已存在，>` 会覆盖它
  - `>>` 会追加到文件后面
- 重命名：
  - mv 是重命名/移动最常用命令
  - 例如：
    - mv old.txt new.txt
    - 文件名从 old.txt 变成 new.txt

16) 参数有什么作用？
- 参数是给命令提供额外信息
- 例如：
  - ls -l
  - ls -a
  - git diff --staged
- 参数决定命令行为：
  - -l: 详细列表
  - -a: 显示隐藏文件
  - --staged: 查看暂存区
- 简单理解：命令本身负责“做什么”，参数负责“怎么做”

17) 返回值可以作为另一个函数的输入参数是什么意思？
- 这点是 C++ 函数概念
- 例如：
  - int add(int a, int b) { return a + b; }
- 这里：
  - a 和 b 是参数
  - 函数返回的值是 a + b
- 这个返回值可以传给其他函数、变量或输出语句：
  - int result = add(3, 5);
  - cout << result << endl;
- 所以：
  - 参数：函数输入
  - 返回值：函数输出

18) C++ 里 add.cpp 编译失败为什么？
报错：
- ‘cout’ was not declared in this scope
- ‘endl’ was not declared in this scope
原因：
- 你写了 cout 和 endl，但没有引入头文件
- 正确写法是：
  - #include <iostream>
  - using namespace std;
- 否则编译器不知道 cout 和 endl 来自哪里

19) “乱码是什么？”
- 这是编码/终端显示问题
- 例如路径里带中文字符，某些命令输出可能出现乱码
- 这通常不是程序错误，而是：
  - 当前终端编码不匹配
  - 文件名包含中文
  - Git 输出的路径在不同 locale 下编码不同
- 解决思路：
  - 统一终端编码 UTF-8
  - 处理文件名时尽量避免中文，或在 UTF-8 环境下运行
