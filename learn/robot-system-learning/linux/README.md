## 3. 重点理解

### 路径

- 绝对路径从 `/` 开始，不依赖当前目录。
- 相对路径以当前目录为起点。
- `.` 表示当前目录，`..` 表示上一级目录。
- `pwd` 默认显示 Shell 维护的逻辑路径；`pwd -P` 会解析符号链接并显示物理路径。路径中没有符号链接时，两者结果可能相同。

### 重定向

- 标准输出的文件描述符是 `1`，用于正常结果。
- 标准错误的文件描述符是 `2`，用于错误和诊断信息。
- `>` 或 `1>` 将标准输出覆盖写入文件。
- `>>` 将标准输出追加到文件末尾。
- `2>` 将标准错误写入文件。
- `2>&1` 让标准错误使用标准输出当前指向的位置。
- `ls > list.txt 2> err.txt` 执行成功时，`err.txt` 为空是正常现象，因为命令没有产生标准错误。
- 重定向可以保存程序运行日志，方便后续检查和定位问题。

### 文本处理

- `grep` 根据条件筛选行，`grep -n` 还会显示行号。
- `sort` 对文本行进行排序，不负责筛选内容。
- `uniq` 合并相邻的重复行，通常与 `sort` 组合使用：`sort file | uniq`。
- `sed -n '1,5p' file` 显示文件第 1 到第 5 行。
- `grep 't*'` 中的 `*` 是正则量词，表示前面的 `t` 出现零次或多次，因此它可能匹配不含 `t` 的行。查找具体文本可使用 `grep 'third' file`。

### Shell 变量和参数

- 普通 Shell 变量默认只属于当前 Shell。
- 使用 `export` 导出的环境变量可以被当前 Shell 启动的子进程继承。
- `$HOME` 保存当前用户的主目录。
- `$PATH` 保存命令搜索目录，多个目录使用 `:` 分隔。
- 变量可以写成 `$name` 或 `${name}`；为避免空格和通配符造成拆分，通常使用 `"$name"`。
- `$0` 是脚本名称，`$1`、`$2` 是第一、第二个位置参数，`"$@"` 表示全部位置参数。
- 执行 `./day3_args.sh robot linux` 时，`robot` 对应 `$1`，`linux` 对应 `$2`。
- `-gt`、`-lt`、`-eq` 分别表示整数大于、小于和等于。
- `while` 在条件成立时继续循环；`until` 在条件成立时结束循环。

### Git 工作区域

- 工作区是正在编辑的文件。
- 暂存区保存下一次提交准备包含的版本，由 `git add` 更新。
- `git commit` 将暂存区内容保存为本地仓库中的提交。
- `git push` 只是把本地提交同步到远程仓库，不是进入提交区的条件。

## 4. 遇到的问题与纠正

### `git restore` 恢复什么

- 默认的 `git restore file` 使用暂存区版本覆盖工作区文件。
- 已被 Git 跟踪的文件不需要在每次恢复前重新执行 `git add`。
- 如果先修改文件并执行 `git add`，随后又继续修改，那么 `git restore file` 会恢复到刚刚暂存的版本。
- 未跟踪文件没有 Git 保存的基准版本，因此普通的 `git restore` 无法恢复它。
- `git restore` 会丢弃工作区修改，执行前应先查看 `git diff`，避免误删有效内容。

### `git stash` 的“保存现场”和“后续恢复”

- “保存现场”是把尚未提交的已跟踪文件修改暂存到 stash，使工作区暂时恢复干净，便于切换任务或分支。
- `git stash list` 用于查看已经保存的现场。
- `git stash pop` 会重新应用最近的现场，并在成功后删除对应的 stash 记录。
- 普通 `git stash` 默认不包含未跟踪文件；需要同时保存未跟踪文件时使用 `git stash -u`。
- 本次练习中的 `temp.txt` 在 stash 后仍显示为未跟踪文件，说明它没有被普通 `git stash` 保存；实际保存的是当时已被 Git 跟踪的文件修改。
