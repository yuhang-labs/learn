## 4. 时间与教学方式

- 默认每周 8～10 小时：工作日每次约 60～75 分钟，周末一次 2～3 小时项目实践，并留机动时间。
- 首轮准备按约 6～9 个月规划；以成果验收而非到期打卡推进，不保证固定时间就业。
- 每次约 15 分钟具体原理、35～50 分钟实验或修改、10 分钟记录。时间不足时拆分，不压缩关键理解。
- AI 提供可运行示例、命令、工作目录、预期行为与必要解释，用户亲自执行。
- 从 C 阶段起逐步采用“运行示例 → 修改一个小功能 → 解释关键逻辑 → 定位一个故障”。修改先给提示，卡住再给完整帮助。
- 不背命令、API 和芯片寄存器表；必须理解与正确性有关的指针有效性、缓冲区边界、生命周期、同步和超时。
- 每日通常检查 2～3 个关键理解点，可由用户修改和调试过程证明，不强制长篇问答或每日总结。
- AI 给出的答案可用于学习，但不能直接作为独立掌握证据；不要求为此重做整天练习。
- 已学内容直接用于项目，不重复上课。只补实际暴露的缺口，不在复查时不断追加验收项。
- 理论优先参考语言与工具文档、芯片参考手册和板卡原理图；每次只选与当前任务有关的小节，用具体示例解释。

## 8. 主项目与硬件安排

主项目：嵌入式数据采集与控制系统。

数据链路：传感器 → STM32/FreeRTOS → UART（先）/CAN（后）→ Linux C++ 设备服务 → 数据记录与控制接口。

- 第一版只在 PC 上完成协议解析与模拟通信，无需立即购买硬件。
- MCU 阶段默认选文档齐全、带调试器的 STM32 Nucleo 类板卡；具体型号需满足 UART、定时器、DMA 和后续 CAN 控制器需求。
- 进入硬件阶段前确认现有设备；需要采购时给出最低清单和兼容性理由，由用户决定购买，不默认用户已有 Jetson 或开发板。
- 最低硬件先覆盖开发板、调试器（可板载）、数据线和一个简单输入；传感器、逻辑分析仪、CAN 收发器与 USB-CAN 按阶段增加。
- MCU CAN 控制器不等于 CAN 收发器；真实总线阶段必须核对收发器、电平和终端。前期不以真实电机运动为练习前提。
- Ubuntu PC 能承担早期 Linux 应用实验；没有 ARM Linux 板卡时记录真实交叉部署为待完成，不能用本机运行冒充。
- 每个版本留源码、构建步骤、接口说明、用户完成的修改、实际验证、限制；不以代码行数作为成果。
