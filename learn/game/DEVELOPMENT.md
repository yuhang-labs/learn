# 执行记录：补充后的开发计划

依据用户提供的完整执行版实施。范围：桌面十二城、三势力、单机与 2～3 真人局域网；不包含联盟、公网匹配、手机适配、自由建造、破坏城门、主机迁移。

| 阶段 | 交付 |
| --- | --- |
| 共享规则与多人状态 | `applyCommand`、`projectState`、独立淘汰、稳定军阵编号、引擎 schema 4、v3 副本迁移 |
| 双层界面与战场 | 现有地图与人物素材、脚本清单、缺失加载阻断、蓝金 UI、镜头与小地图、地形网格、寻路／避让／射线、遮挡和姿态 |
| 单机与 AI | 建设、征募、驻将、调兵、攻城与援军、胜负、命名与自动存档；同一规则下的 AI 预算与诊断 |
| 局域网 | ws 权威服务器、大厅席位、按视野同步、去重／限流、投票、掉线宽限、AI 接管与原身份重连、服务器存档和恢复大厅 |
| 综合验收 | 规则及 WebSocket 测试、三浏览器会话、两种分辨率、300 军阵模拟与渲染测试；结果见 ACCEPTANCE.md |

用户补充的地理要求：城池不能按画面空位摆放，必须按真实地区判断。`assets.js` 增加十二处地区说明与经纬度锚点，再结合风格化底图手工标定；巴蜀以四川成都为锚点，位于咸阳西南。战略时间仍由独立旧坐标决定。

必要的测试变化：旧战术测试的 `(40,40)` 在新城图中是建筑，改为先验证该点不可达，再验证道路上的 `(61,50)` 可达。完整自动统一测试的截止从 3600 调整为 7200 游戏秒，因为新地图必须真实通过城门、道路并处理拥堵；没有改变经济、伤害或 AI 操作预算来让测试通过。

已发现并修复的问题：初期招募军阵与已有军阵重叠、狭窄通道拥堵、隔墙目标没有合适射击点、Canvas 调整尺寸后瞬间空白、局域网普通 HTTP 下不可用的 randomUUID、非法原型属性建设命令、命令失败时意外生成驻军、恢复对局后的结果去重。最终代码使用随机字节生成浏览器标识，不依赖安全上下文中的 randomUUID。

仍需现场执行：两台物理电脑的局域网连通、防火墙、无线抖动和真实网络断开恢复。当前只有同机真实 WebSocket 与独立浏览器会话实测。素材是有限分辨率姿态样本，地形与遮挡是手工近似；完整美术八方向动画和地图精细建模不在本版交付范围。
