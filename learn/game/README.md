# 大秦 · 天下归一

桌面浏览器古代策略游戏：十二城、秦／波斯／罗马三方，世界调兵与城市实时战斗共用兵力、将领和伤亡。支持离线单机与局域网 2～3 名真人，空位由 AI 补齐。单机和联机使用同一套命令、视野、经济、寻路与战斗规则。

## 启动

单机：直接打开本目录 `index.html`，或把整个目录作为 GitHub Pages 子目录发布。无需安装依赖、无需联网。保留 `assets/` 目录与相对路径。

局域网：安装 Node.js 18 或更新版本，在本目录执行：

```bash
npm ci
npm start
```

默认监听 `0.0.0.0:8080`，终端打印本机局域网地址。其他电脑访问该地址，在「局域网 · 房间大厅」填写昵称、创建或加入六位房间号、选择空闲势力、准备；创建者点击开始。空席位由 AI 控制。端口占用可执行 `PORT=8081 npm start`（Linux/macOS）；PowerShell 使用 `$env:PORT=8081; npm start`。

服务进程独立于浏览器；关闭创建者页面不会结束服务。服务器不自动配置防火墙、不实现主机迁移，也不提供公网匹配、联盟或手机适配。GitHub Pages 只支持静态单机，不能运行 Node.js 房间服务。

## 操作

| 场景 | 操作 |
| --- | --- |
| 世界地图 | 左键选城／拖框选择己方城池，Shift 追加 |
| 配兵 | 右键相邻目标，输入各兵种、主将和阵型；全军／一半；Enter 下令 |
| 进入城市 | 双击可见城池，或详情中「进入城市」 |
| 城市作战 | 框选己方军阵，右键地面移动、可见敌军攻击 |
| 战术 | S 驻守、A 迎敌；守方可点击「城内集结」 |
| 镜头 | 滚轮缩放，中键拖动，小地图点击定位 |
| 返回 | Esc 取消配兵／返回世界，或「← 天下」 |
| 暂停 | 空格／顶部按钮；联机为投票或恢复 |
| 存档 | 顶部「存档」或 Ctrl / Cmd + S |

城池详情按需展开，左侧城池导航、右侧势力图例、右下小地图、底部配兵或军阵命令保持可用。所有点击、框选、行军线与小地图共享镜头变换。

批量出兵先整体校验，再整体执行；任何来源失败均不扣兵、不扣粮。可以留守零人，将领没有硬性带兵上限。每军阵最多 20 人，只显示一个代表士兵，数字才是真实人数。选中或悬停显示兵种与人数，标签避让相邻人物；密集时以底部选中列表为准。侧栏独立占位，不覆盖战场。

己方和平城市完整显示地形；交战时视野外地形使用柔和暗色遮罩，保留屋顶与道路。未进入的敌城仍隐藏城内情报，敌军严格按真实视线显示，不因地形可见而暴露。

## 地理、美术与战场

世界图城池以真实地区为锚点：咸阳在陕西关中，巴蜀在四川盆地成都一带、位于咸阳西南；漠北在蒙古高原；天竺在印度北部；波斯在伊朗高原；巴比伦在伊拉克；南洋在马来半岛；埃及在尼罗河下游；迦太基在突尼斯；罗马在意大利；高卢在法国；玛雅在尤卡坦半岛。精确地区说明、地理经纬度锚点与底图显示坐标存于 `assets.js`。

底图是风格化架空画面，不是精确投影地图。根据可见海岸、山脉和地区关系手工标定显示坐标；行军时间仍按旧战略坐标计算，调整美术落点不改变行军时长。

古城图原生 975×524、世界图原生 1536×499。城市初始镜头等比例铺满战场区域，超出的边缘可拖动查看；拖动限制在地图边界，主动缩小后可查看全图。世界初始镜头不超过原生大小。放大只放大现有像素，不增加素材细节。代表士兵统一按原图 28×28 像素尺寸绘制，再与地图同步等比例缩放。建筑与地面在同一张图中，`navigation.js` 手工标定建筑、水域、桥梁、墙段、常开城门、出生区和集结点，使用 100×100 通行网格。建筑与墙同时阻挡行走和视线，弓兵也不能隔墙射击。军阵使用共享寻路、可射击落点、局部避让与拥堵重寻路；不可达军令明确拒绝。

兵种使用筛选姿态：待机第 0 帧，移动／攻击第 0、1 帧，死亡第 0 帧静态倒地；不是完整八方向连续动画。统一落脚点和纵深排序，建筑／墙的标定区域作前景遮挡。遮挡范围是手工近似，不能等同于可拆建筑模型。本版不做城门破坏或自由摆放建筑。

素材通过脚本清单加载，兼容 `file://`，不请求 JSON 清单。加载窗口显示进度及缺失文件，缺失素材时阻止开始并可重试。原图和派生素材均保留，详见 `assets/processed/README.md`。

## 规则、视野与 AI

完整战局保留在单机模拟闭包或服务器，UI 只读取 `projectState(state, faction)`。建设、征募、驻将、阵型、批量调兵和战术命令统一经 `applyCommand(state, actor, command)`；AI 使用同一入口。战术每 100 毫秒推进，经济、伤亡和 AI 时钟仍按游戏秒结算，画面只插值位置。

世界地形始终可见，未知城池及其归属、兵力隐藏；已知邻城可侦察。敌军行军仅在两端可见时显示。城内按军阵、守方集结区域和建筑／墙遮挡计算视线；不可见敌军不传给客户端。失去目标后只能前往最后可见位置。战报按发生时的合法受众筛选，服务器不会发送其他势力私有资源、完整战局、身份凭据或诊断数据。小地图也仅使用同一可见快照。淘汰玩家不获得全图视野。

初始每势力两城、三将、320 金、300 粮、280 兵。每城每秒收入 `1 + 2 × 民居等级` 金、`1 + 农田等级` 粮，初始两城合计 6 金／秒。招募 20 人耗 32 金、24 粮，冷却 `12 / 兵营等级` 秒。

AI 开局 45 秒准备，每势力每 8 个游戏秒至多一道成功命令，建设、征兵、调兵和战术共用预算。发现可见来袭军队至少等待 6 秒才响应。普通包含发展、扩张、防守、增援和集结；困难增加克制和集火判断，不加资源、不加伤害。

同时抵达按到达时间、军队编号排序；守方援军立即补入战斗，其余进攻者等待，前战结束后按最新归属增援或攻击。切换地图不停止模拟。失去全部城池的势力淘汰，其远征军解散；单机玩家淘汰可结束本局，联机其余势力继续，直到一方占领十二城。结果以持久战局编号和势力去重，刷新／重连不重复记账。

## 联机暂停与掉线

联机固定一倍速，菜单、存档窗口及后台不暂停全局。仅一名参战真人且未被 AI 接管时可直接暂停；多人须全票同意，投票 15 秒过期。任意有效参战真人可以恢复，暂停最长 120 秒，暂停期间拒绝军令。

每席位每局首次掉线全局等候最多 30 秒，多人同时掉线共用等候截止时间。超时 AI 接管，后续掉线立即接管；原浏览器凭本机身份重连取回势力，资源、军队与 AI 预算不重置。同一席位新连接会替换旧连接。重连取消未完成的投票。以上截止时间使用服务器现实时间，不受游戏暂停影响。

## 存档与诊断

- 单机自动存档每 12 游戏秒、成功军令和打开菜单时更新；最多 12 个命名存档，支持读取、覆盖、删除。读取后暂停。浏览器网站数据不可用时明确提示。
- 新单机键为 `daqin-save-v4`、`daqin-slots-v4`，引擎 `schema=4`；原 `version=1` 保留为历史封装版本。旧 v3 自动／手动存档读取副本迁移，不再次清除旧键。迁移保留兵力、资源、将领、军令时钟；旧战场位置因新障碍布局重建，新 v4 保存路径和战术状态完整恢复。
- 联机协议版本独立为 `v=1`。命令有房间、命令编号及服务器序号，服务端去重、限流、校验权限并返回失败原因。
- 联机完整存档在服务器 `server-data/`，由临时文件写入后原子替换；静态服务不暴露此目录。自动档每 12 秒写入，创建者可另存、覆盖、删除；删除文件改名为 `.json.deleted`，管理员可恢复文件名。
- 联机读档进入等待大厅，不能回滚正在运行的房间。原席位默认等待，创建者可明确改为 AI 代管；陌生身份不能占用原席位。席位身份与已用掉线宽限随存档持久化，重启后创建者仍凭原浏览器身份恢复管理权。
- 本机重连身份在 `daqin-lan-identity-v1`。请固定访问地址和浏览器，清除网站数据会失去原身份。服务器只保存身份哈希，不将身份发给其他玩家。
- 「导出记录」仅导出本人可见状态和本势力诊断。单机记录收入、支出、伤亡、失城与军令时间；联机终局记录包含本人诊断，淘汰后冻结自己的终局信息。不是无限长度逐操作录像。

## 连接排错与两台电脑验收

1. 电脑 A 启动服务，记下终端打印的 `http://192.168.x.x:8080`；先在 A 本机访问验证页面可用。
2. 电脑 B 与 A 在同一局域网，访问 A 的局域网地址，不能用 `localhost`。若不通，核对地址、端口、访客 Wi-Fi 隔离及系统防火墙的入站端口规则；本程序不会改防火墙。
3. A 创建房间，B 加入，双方选择不同势力并准备，A 开始；检查双方资源独立、未知城池隐藏，空位 AI 正常行动。
4. 验证 A 单独投暂停不生效，B 同意后暂停；任一方恢复。断开 B 网络，首次最多等候 30 秒后 AI 接管；恢复 B 网络或刷新后用原浏览器加入原房间，应取回势力且兵力不重置。
5. B 再次掉线应立即 AI 接管；同时断网不应叠加宽限。关闭 A 浏览器，B 游戏应继续；停止 A 的 Node 服务则全部断线，无主机迁移。
6. A 保存，停止并重启服务；原浏览器通过服务器存档恢复。B 不在线时保持等待，A 明确选择 AI 代管后才能开始；B 之后仍可凭原身份取回席位。

实际验收结果和未覆盖项见 `ACCEPTANCE.md`。目前没有两台物理电脑的跨设备实测，不把同机三会话测试当作跨设备验收。

## 验证与文件结构

```bash
npm test
node tools/stress.cjs
```

浏览器检查脚本使用 Playwright。开发机已安装 Playwright 和 Chromium 时执行 `node tools/browser_check.cjs`；默认测试服务地址 `http://127.0.0.1:8188`，可用 `TEST_URL` 配置。`PLAYWRIGHT_MODULE` 可指定现有 Playwright 模块，`PLAYWRIGHT_BROWSERS_PATH` 可指定浏览器目录。压力渲染使用 `tools/browser_stress.cjs`。

├── index.html / style.css / app.js   双层 UI、镜头、单机存档、房间客户端

├── navigation.js                   地形标定、通行网格、寻路和空间索引

├── server.js                       HTTP / WebSocket、席位、现实时间时钟、存档
├── package.json / package-lock.json ws 依赖与锁文件
├── engine.test.js / rules.test.js / server.test.js
├── tools/
│   ├── prepare_assets.py
│   ├── browser_check.cjs
│   ├── browser_edges.cjs
│   ├── browser_display.cjs          离线显示、兵团标签、布局与迷雾回归

游戏开发不推进学习日、不修改学习输出，不自动提交或推送 Git。`node_modules/`、服务器存档、身份及日志均忽略，代码、原图、派生素材和依赖锁文件可随项目推送。
