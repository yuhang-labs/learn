# 整理后的游戏素材

原图保留在上一级目录，本目录为裁切和背景清理后的派生文件，现已接入世界图、城市图及军阵显示。浏览器通过 `../../assets.js` 脚本清单加载，不通过 fetch 请求 JSON，支持直接打开网页及 Pages 子目录。

## 地图

- `world-map.png`：1536×499，取自 `daqin-reference-sheet.png` 的顶部，无界面文字。
- `city-scene.png`：975×524，取自同一原图左下方，建筑与地面为一体。
- 选择这张原图是因为其地图区域比后续拼图中的地图区域更大。没有放大补像素，也没有生成新的画面细节。

## 兵种

`troops/cavalry`、`troops/archer`、`troops/spearman` 分别为骑兵、弓兵、枪兵。

每个目录包含 `idle`（待机）、`move`（移动）、`attack`（攻击）、`death`（死亡）、`poses`（补充姿态）。每组提供一张横向图集和编号单帧，例如 `move.png`、`move-00.png`。

- 单帧统一 128×128 透明 PNG，底部对齐点为 `(64, 112)`，人物保持原生像素尺寸。
- `manifest.json` 记录裁切来源、源文件哈希、图集位置、帧数及建议播放速度。
- `troop-preview.jpg` 将透明帧叠在不同背景上，用于检查边缘；预览图本身不透明。
- 原始棋盘格已去除，并清理远离人物的小碎片。明亮金属、细长兵器的边缘可能有损失，源图像素不足之处无法恢复。
- 原图提供的是不同姿态样本，不是经过验证的连续动作；`poses` 没有可靠的八方向标签，不能当成完整八方向动画。
- 死亡行包含多种倒地姿态，并非逐帧倒下过程。接入时优先选择一帧作为遗体，不应将全部帧循环播放。
- 原画局部构图和武器长度不一致；统一画布和落脚点不能消除所有动作跳变。建议游戏中以接近原生尺寸显示。
- 当前使用待机第 0 帧、移动与攻击第 0/1 帧交替、死亡第 0 帧静态倒地；不用 poses 冒充八方向动画。每军阵仅一个代表士兵，统一以 28×28 像素尺寸绘制并随城市镜头等比例缩放，落脚点按原 `(64,112)` 等比变换。真实人数在选中／悬停标签与底部列表中显示。
- 城市碰撞和遮挡来自 `../../navigation.js` 手工标定的多边形与墙段；这些是玩法近似，不是自动从图像提取的精确建筑模型。

## 重建

安装 Pillow 后，在项目根目录运行 `python3 game/tools/prepare_assets.py`。脚本仅重建本目录的派生图片与清单，不修改原图或游戏代码。
