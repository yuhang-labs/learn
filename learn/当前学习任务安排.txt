Day18 详细学习安排：ip addr 与 ip link

- 理解网络接口是系统中的网络收发对象，`ip link` 查看接口本身及链路状态。

- 能区分“接口存在”“接口处于 UP”“接口具有地址”这三类信息。

二、理解接口、链路与地址

任务 1：建立整体概念

```text
系统中的网络接口（本次只看 lo）
             ↓
ip link 查询接口是否存在及链路属性/状态
             ↓
ip addr 查询该接口上配置的 IPv4/IPv6 地址
             ↓
脚本汇总为简洁诊断输出
```

重点理解：

- `ip link` 关注接口对象、链路层属性和状态。
- `ip addr` 关注接口上分配的网络层地址，也会同时显示所属接口信息。
- 接口存在不等于它一定有 IP 地址。
- 接口显示 `UP` 不等于外部网络一定可达。
- `lo` 是回环接口，常见地址为 IPv4 `127.0.0.1` 和 IPv6 `::1`，通信不会离开本机。
- 回环接口的简洁状态可能显示 `UNKNOWN`；这不应脱离 flags 和地址信息单独判断为故障。

验证标准：

- 后续能按“接口存在 → 链路信息 → 地址信息”的顺序解释检查结果。

四、使用 ip link 检查回环接口

任务 3：查看详细链路信息

执行：

```bash
ip link show dev lo
```

观察重点：

- 第一行中的接口名称 `lo` 证明查询到了目标接口。
- flags 中常见 `LOOPBACK` 和 `UP`，分别说明它是回环接口以及管理状态已启用。
- `mtu` 是该接口单个数据包的传输大小限制之一，本日只需知道它属于链路属性。
- `link/loopback` 表明链路类型是回环，不是真实以太网卡。

验证标准：

- 保留完整输出，并指出接口名称、`LOOPBACK` 和 `UP`。

任务 4：查看简洁链路信息

执行：

```bash
ip -brief link show dev lo
```

重点理解：

- `-brief` 将结果压缩为适合快速查看和脚本报告的一行。
- 简洁输出通常包含接口名称、状态和链路地址。
- `lo` 可能显示 `UNKNOWN`，但详细 flags 中仍可看到 `UP`；这两项描述的角度不同。
- 判断时应结合接口类型、flags 和地址，不能只看一个状态词。

验证标准：

- 保留简洁输出，并能说明它与详细输出是同一个接口的不同展示形式。

五、使用 ip addr 检查回环地址

任务 5：查看详细地址信息

执行：

```bash
ip addr show dev lo
```

观察重点：

- 输出包含接口的链路信息，以及该接口上的地址信息。
- `inet` 行表示 IPv4 地址，`inet6` 行表示 IPv6 地址。
- `scope host` 表示该地址的作用范围在本机。
- `/8`、`/128` 是地址前缀长度，本日只需理解它们是地址的一部分，不要求计算。

验证标准：

- 保留完整输出，并找到 IPv4、IPv6 和 `scope host`。

任务 6：查看简洁地址信息

执行：

```bash
ip -brief addr show dev lo
```

重点理解：

- 简洁地址输出把接口名称、状态和地址集中在一行。
- `ip -brief link` 更适合快速看链路，`ip -brief addr` 更适合快速看地址。
- 地址输出中出现 `127.0.0.1/8` 或 `::1/128`，只证明本机回环地址已配置。

验证标准：

- 保留简洁输出，并能区分 link 输出与 addr 输出各自增加的重点信息。

六、验证接口不存在的异常场景

任务 7：查询明确不存在的练习接口

执行：

```bash

printf 'missing interface status=%s\n' "$missing_status"
```

预期：

- `ip` 输出找不到设备的错误。
- `missing_status` 为非 0，表示命令没有成功找到目标接口。

重点理解：

- “接口不存在”应先检查输入的接口名称。
- 它与“接口存在但没有 IPv4/IPv6 地址”是两种不同情况。
- 不要为了消除错误而创建、启用或修改真实接口。

验证标准：

- 保留错误文字和非 0 状态。
- 能说明错误来自接口名称，而不是 IP 地址内容。

七、创建网络接口检查脚本

任务 8：为 Robot System Diagnostic Tool 创建项目脚本

执行：

```bash
cd "$HOME/workspace/learn/learn/robot-system-learning/linux"
vim network_interface_check.sh
```

在 Vim 中写入下面的完整内容：

```bash
#!/bin/bash

interface_name="$1"

if [[ -z "$interface_name" ]]; then
    printf '%s\n' '[NETWORK CHECK ERROR] interface name is required' >&2
    exit 1
fi

if ! ip link show dev "$interface_name" >/dev/null 2>&1; then
    printf '[NETWORK CHECK ERROR] interface not found: %s\n' "$interface_name" >&2
    exit 1
fi

printf '[NETWORK LINK] interface=%s\n' "$interface_name"
ip -brief link show dev "$interface_name"

printf '[NETWORK ADDRESS] interface=%s\n' "$interface_name"
ip -brief addr show dev "$interface_name"
```

保存后执行：

```bash
bash -n network_interface_check.sh
chmod u+x network_interface_check.sh
ls -l network_interface_check.sh
cat network_interface_check.sh
```

脚本整体逻辑：

1. 接收一个接口名称。
2. 没有输入时输出错误并停止。
3. 使用 `ip link show dev` 判断接口是否存在。
4. 接口不存在时输出明确错误并停止。
5. 接口存在时依次输出简洁链路信息和地址信息。

重点理解：

- 脚本只查询，不修改接口。
- 接口存在性检查放在地址查询之前，可以区分对象不存在与地址结果为空。
- 所有接口名称都用引号保护，输入始终作为一个参数处理。

验证标准：

- `bash -n` 没有输出，表示没有发现 Shell 语法错误。
- 权限中 owner 具有 `x`。
- 文件内容与上面的完整脚本一致。

十一、机器人系统中的位置

```text

          ↓
先用 ip link 确认接口存在并读取链路状态
```
