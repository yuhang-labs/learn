三、字面量搜索与正则表达式

任务 2：观察容易产生误匹配的写法

执行：

```bash
grep -n -- '[ERROR]' "$practice_dir/error.log"

grep -Fn -- '[ERROR]' "$practice_dir/error.log"
```

重点理解：

- 普通 `grep` 会把 `[ERROR]` 当作正则表达式，其中方括号表示“匹配其中任意一个字符”，因此可能匹配很多不相关的行。
- `grep -F` 把 `[ERROR]` 当作完整的普通文字，适合查找固定日志标签。
- 日志标签是固定文本时，优先使用字面量搜索，意图更明确。

验证标准：

- 第一条命令可能显示不只两行错误日志。
- 第二条命令只显示包含完整 `[ERROR]` 标签的两行。
- 能用自己的话说明误匹配的原因，不要求背正则语法。

任务 3：在需要表达变化时使用正则

执行：

```bash
grep -En -- 'temp=[0-9]+' "$practice_dir/error.log"

grep -En -- '\[(ERROR|WARN)\]' "$practice_dir/error.log"
```

重点理解：

- `-E` 启用扩展正则表达式。
- `temp=[0-9]+` 表示查找 `temp=` 后面跟一个或多个数字的内容。
- `(ERROR|WARN)` 表示匹配 `ERROR` 或 `WARN`。
- 固定文本使用 `-F`，需要表达“数字范围、多个可能模式”等变化时再使用正则。

验证标准：

- 第一条只找到温度行。
- 第二条找到一行警告和两行错误。
- 能判断某个需求更适合字面量还是正则搜索。

四、查看故障上下文

任务 4：保留错误发生前后的证据

执行：

```bash
grep -Fn -C 1 -- '[ERROR]' "$practice_dir/error.log"
```

重点理解：

- 只看错误行可能不知道故障前后发生了什么。
- `-C 1` 同时显示匹配行前后各一行。
- 在机器人系统中，上下文可以帮助判断错误发生前的状态和错误后的恢复动作。

验证标准：

- 输出包含错误行及相邻上下文。
- 能指出 `motor timeout` 后出现了 `retry motor`。
- 能说明上下文比只看单独错误行多提供了什么证据。

五、项目实践：日志等级分析器

任务 5：创建 `day6_log_analyzer.sh`

文件位置：

```text
robot-system-learning/linux/day6_log_analyzer.sh
```

完整代码：

```bash
#!/bin/bash

log_file="${1:-}"

if [ -z "$log_file" ] || [ ! -f "$log_file" ]; then
    echo "[ANALYZER ERROR] log file not found: $log_file" >&2
    exit 3
fi

error_count=$(grep -F -c -- '[ERROR]' "$log_file")
warning_count=$(grep -F -c -- '[WARN]' "$log_file")

echo "Log file: $log_file"
echo "ERROR count: $error_count"
echo "WARN count: $warning_count"

if [ "$error_count" -gt 0 ]; then
    echo "--- ERROR evidence ---"
    grep -Fn -C 1 -- '[ERROR]' "$log_file"
    echo "[STATUS] ERROR"
    exit 2
fi

if [ "$warning_count" -gt 0 ]; then
    echo "--- WARN evidence ---"
    grep -Fn -C 1 -- '[WARN]' "$log_file"
    echo "[STATUS] WARN"
    exit 1
fi

echo "[STATUS] HEALTHY"
exit 0
```

整体流程：

1. 接收一份日志文件作为输入。
2. 输入文件不存在时立即报告错误。
3. 分别统计固定标签 `[ERROR]` 和 `[WARN]`。
4. 有错误时优先输出错误证据并返回 `2`。
5. 没有错误但存在警告时输出警告证据并返回 `1`。
6. 两者都没有时报告健康并返回 `0`。

要求：

- AI 已提供完整代码，用户只需创建文件、运行并理解整体流程。
- 不要求记住 `grep` 的组合参数。
- 不给脚本增加自动修改或删除日志的功能；分析工具只读取证据。
