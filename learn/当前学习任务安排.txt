二、准备包含中间故障的测试日志

任务 1：在 `/tmp` 中创建固定测试日志

执行：

```bash
practice_dir='/tmp/day7-view-practice'
mkdir -p "$practice_dir"

for number in $(seq 1 40); do
    case "$number" in
        20) printf '%02d [WARN] motor temperature rising\n' "$number" ;;
        21) printf '%02d [ERROR] motor timeout\n' "$number" ;;
        22) printf '%02d [RECOVERY] motor restarted\n' "$number" ;;
        *)  printf '%02d [INFO] robot running\n' "$number" ;;
    esac
done > "$practice_dir/robot.log"

wc -l "$practice_dir/robot.log"
```

预期：日志共 40 行，警告、错误和恢复信息位于中间位置。

重点理解：

- 测试日志放在 `/tmp`，不提交到项目仓库。
- 中间故障用于验证“只看开头或结尾可能漏掉问题”。
- 不要求理解或记忆生成日志的循环细节。

验证标准：

- `wc -l` 显示 40 行。
- 能说明故障信息为什么故意放在日志中间。

三、按查看目的选择工具

任务 2：比较完整输出、首部和尾部

执行：

```bash
cat "$practice_dir/robot.log"

head -n 5 "$practice_dir/robot.log"

tail -n 5 "$practice_dir/robot.log"
```

观察并回答：

- `cat` 显示整个文件，能看到中间故障，但大文件会产生大量终端输出。
- `head` 适合快速确认文件开头、标题或启动阶段。
- `tail` 适合快速确认文件结尾和最近记录。
- 本次 `head` 和 `tail` 都看不到第 20～22 行的故障过程。

验证标准：

- `cat` 输出 40 行完整日志。
- `head` 只看到开头的正常记录。
- `tail` 只看到结尾的正常记录。
- 能说明首尾快照为什么不能代表整份日志没有错误。

任务 3：使用 `less` 搜索中间故障

执行：

```bash
less "$practice_dir/robot.log"
```

进入 `less` 后按顺序操作：

```text
/ERROR    搜索 ERROR
n         跳到下一个匹配
g         回到文件开头
G         跳到文件结尾
q         退出 less
```

重点理解：

- `less` 分页显示文件，不会一次把全部内容刷到终端。
- 可以在文件内搜索并前后移动，适合人工查看较大的日志。
- 这些按键不要求记忆，需要时查看帮助即可。

验证标准：

- 能在 `less` 中定位到第 21 行的 `motor timeout`。
- 能正常退出并回到 Shell。
- 在 `out.md` 中记录是否找到错误，不需要复制整个交互界面。

四、实时观察日志新增内容

任务 4：使用两个终端观察日志更新

先创建实时日志：

```bash
printf '%s\n' \
    '12:00:00 [INFO] monitor started' \
    '12:00:01 [INFO] waiting for data' \
    > "$practice_dir/live.log"
```

在终端 A 执行：

```bash
tail -n 2 -f /tmp/day7-view-practice/live.log
```

保持终端 A 运行，在终端 B 执行：

```bash
printf '%s\n' '12:00:02 [WARN] sensor delayed' >> /tmp/day7-view-practice/live.log
printf '%s\n' '12:00:03 [INFO] sensor recovered' >> /tmp/day7-view-practice/live.log
```

观察终端 A 出现两条新记录后，按 `Ctrl+C` 停止跟踪。

重点理解：

- 普通 `tail` 是一次性快照。
- `tail -f` 会继续等待并显示文件后续新增内容。
- `Ctrl+C` 是停止当前前台命令，不会删除日志。
- 实时跟踪适合观察正在运行的机器人节点、服务或测试程序。

验证标准：

- 终端 A 先显示原有两行，之后显示终端 B 追加的两行。
- 停止跟踪后 `live.log` 仍然存在且内容完整。
- 能说明实时跟踪与一次性查看的区别。

五、项目实践：日志首尾快照工具

任务 5：创建 `day7_log_snapshot.sh`

文件位置：

```text
robot-system-learning/linux/day7_log_snapshot.sh
```

完整代码：

```bash
#!/bin/bash

log_file="${1:-}"
line_count="${2:-5}"

if [ -z "$log_file" ] || [ ! -f "$log_file" ]; then
    echo "[SNAPSHOT ERROR] log file not found: $log_file" >&2
    exit 1
fi

if ! [[ "$line_count" =~ ^[1-9][0-9]*$ ]]; then
    echo "[SNAPSHOT ERROR] line count must be a positive integer: $line_count" >&2
    exit 1
fi

total_lines=$(wc -l < "$log_file")

echo "Log file: $log_file"
echo "Total lines: $total_lines"
echo "--- First $line_count lines ---"
head -n "$line_count" "$log_file"
echo "--- Last $line_count lines ---"
tail -n "$line_count" "$log_file"

if [ "$total_lines" -gt $((line_count * 2)) ]; then
    echo "[NOTICE] middle content is not included in this snapshot"
fi
```

整体流程：

1. 接收日志文件和希望查看的行数，默认查看首尾各 5 行。
2. 先确认日志文件存在，行数参数有效。
3. 统计日志总行数。
4. 分别输出文件开头和结尾的快照。
5. 文件中间还有内容时，明确提示快照未包含中间部分。

要求：

- AI 已提供完整代码，用户只需创建文件、运行并理解整体流程。
- 不要求学习脚本中的正则细节或数字退出状态。
- 脚本只读取日志，不修改或删除日志。
