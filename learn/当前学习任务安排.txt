二、理解普通变量与环境变量

任务 1：观察当前 Shell 和子进程看到的变量

执行：

```bash
DAY10_LOCAL='local-value'
export DAY10_ENV='environment-value'

printf 'current shell local: %s\n' "$DAY10_LOCAL"
printf 'current shell environment: %s\n' "$DAY10_ENV"

bash -c 'printf "child local: %s\n" "${DAY10_LOCAL:-<empty>}"; printf "child environment: %s\n" "${DAY10_ENV:-<empty>}"'
```

预期：

- 当前 Shell 能看到 `DAY10_LOCAL` 和 `DAY10_ENV`。
- 新启动的子进程中，`DAY10_LOCAL` 显示 `<empty>`。
- 子进程能看到 `DAY10_ENV` 的 `environment-value`。

整体逻辑：

```text
普通 Shell 变量：当前 Shell 使用
导出的环境变量：当前 Shell 使用，它启动的子进程也能继承
```

重点理解：

- 两者都能在当前 Shell 中使用，核心差别是是否会传给子进程。
- `export` 的整体作用是将变量加入子进程可继承的环境。
- 这个实验只要看懂输出差异，不要求解释 `${...:-...}` 的语法。

验证标准：

- 真实输出与上述预期一致。
- 能根据输出说明：普通变量没有自动传给子进程，导出的环境变量会被继承。

三、观察 PATH 与命令查找

任务 2：将 `PATH` 中的目录逐行显示，并查看命令的真实位置

执行：

```bash
printf '%s\n' "$PATH" | tr ':' '\n'
command -v bash
command -v ls
command -v day8_diagnostic_pipeline.sh || printf '%s\n' '[NOT FOUND] day8 script is not in PATH'
```

预期：

- `PATH` 被拆成多个搜索目录，通常包含 `/usr/bin`、`/bin` 等位置。
- `bash` 和 `ls` 能显示可执行文件位置。
- 未将项目的 Linux 目录加入 `PATH` 时，`day8_diagnostic_pipeline.sh` 通常显示 `[NOT FOUND]`。

整体逻辑：

```text
输入命令名 → Shell 按 PATH 的目录顺序查找 → 找到可执行文件 → 运行
```

重点理解：

- `PATH` 保存的是搜索目录，不是某一条命令的路径。
- Shell 按顺序搜索，同名命令时前面的目录优先。
- `command -v` 用来确认 Shell 实际会使用哪个命令，不要求背它的参数。

验证标准：

- 保留逐行显示的 `PATH` 和两个系统命令位置。
- 能指出 Shell 是在哪些目录中寻找命令。

四、用最小实验验证 PATH

任务 3：创建一个临时命令，先用完整路径运行，再通过 `PATH` 运行

执行：

```bash
mkdir -p /tmp/day10-bin
vim /tmp/day10-bin/robot-health
```

在 Vim 中写入下面的完整内容：

```bash
#!/bin/bash

echo '[ROBOT] health check ready'
```

保存后执行：

```bash
chmod +x /tmp/day10-bin/robot-health
/tmp/day10-bin/robot-health

command -v robot-health || printf '%s\n' '[NOT FOUND] robot-health is not in PATH'

export PATH="/tmp/day10-bin:$PATH"
command -v robot-health
robot-health
```

预期：

- 使用完整路径时，命令一开始就能运行。
- 加入 `PATH` 前，只输入 `robot-health` 时 Shell 找不到它。
- 将 `/tmp/day10-bin` 放入 `PATH` 后，`command -v` 显示 `/tmp/day10-bin/robot-health`，直接输入命令名也能运行。

重点理解：

- 完整路径直接指向文件，不依赖 `PATH` 搜索。
- 只写命令名时，Shell 必须借助 `PATH` 找到它。
- 命令文件存在不代表只写名字就能运行；还要有执行权限，并且所在目录可被搜索。

验证标准：

- 保留加入 `PATH` 前后 `command -v robot-health` 的实际结果。
- 加入 `PATH` 后，`robot-health` 显示 `[ROBOT] health check ready`。

五、故意破坏 PATH 并恢复

任务 4：观察错误的 `PATH` 为什么会让系统命令“消失”

严格按以下顺序执行：

```bash
saved_day10_path="$PATH"
PATH='/tmp/day10-bin'

command -v robot-health
command -v ls || printf '%s\n' '[NOT FOUND] ls is not in the current PATH'
ls

PATH="$saved_day10_path"
command -v ls
ls --version | head -n 1
```

预期：

- `PATH` 只保留 `/tmp/day10-bin` 时，`robot-health` 仍能被找到。
- `ls` 的文件仍然存在，但它所在的系统目录不在当前 `PATH` 中，因此只输入 `ls` 会失败。
- 恢复保存的 `PATH` 后，`ls` 重新能被找到并执行。

重点理解：

- “命令找不到”不等于软件一定没有安装，也可能是 `PATH` 中缺少它所在的目录。
- 更新 `PATH` 时应保留原有目录，不能只留项目自己的目录。
- 出现异常时先检查：命令文件是否存在、是否可执行、它所在目录是否在 `PATH` 中。

验证标准：

- 保留 `ls` 失败和恢复后成功的真实输出。
- 恢复后的 `PATH` 与 `saved_day10_path` 一致。

六、项目实践：robot_env.sh

任务 5：创建原计划指定的项目环境文件

文件位置：

```text
robot-system-learning/linux/robot_env.sh
```

执行：

```bash
cd ~/workspace/learn/learn/robot-system-learning/linux
vim robot_env.sh
```

在 Vim 中写入下面的完整内容：

```bash
#!/bin/bash

export ROBOT_PROJECT_ROOT="$HOME/workspace/learn/learn/robot-system-learning"
export ROBOT_LOG_DIR="/tmp/robot-system-logs"
export PATH="$ROBOT_PROJECT_ROOT/linux:$PATH"
```

先检查文件，再加载：

```bash
bash -n robot_env.sh

unset ROBOT_PROJECT_ROOT ROBOT_LOG_DIR
source ./robot_env.sh

printf 'project root: %s\n' "$ROBOT_PROJECT_ROOT"
printf 'log directory: %s\n' "$ROBOT_LOG_DIR"
command -v day8_diagnostic_pipeline.sh

mkdir -p "$ROBOT_LOG_DIR"
test -d "$ROBOT_LOG_DIR" && printf '%s\n' '[OK] robot log directory exists'
```

预期：

- `bash -n` 没有语法错误。
- `ROBOT_PROJECT_ROOT` 显示项目目录，`ROBOT_LOG_DIR` 显示 `/tmp/robot-system-logs`。
- 加载后，`command -v day8_diagnostic_pipeline.sh` 显示项目中脚本的完整路径。
- 日志目录存在时显示 `[OK] robot log directory exists`。

整体流程：

1. `robot_env.sh` 集中定义机器人项目根目录和日志目录。
2. 它将项目的 Linux 脚本目录放到现有 `PATH` 前面，同时保留原来的系统目录。
3. 加载文件后，配置进入当前 Shell。
4. 当前 Shell 可以把这些环境变量传给后续启动的项目脚本或程序。
5. Shell 可根据新的 `PATH` 直接找到项目诊断脚本。

- AI 已提供 `robot_env.sh` 完整内容，用户只需创建、加载、运行并理解整体逻辑。
- 不要求背 `export` 或 `source` 的语法。
- 不要在今天修改 `~/.bashrc` 或其他用户级配置，避免在尚未完成 Day11 `source` 学习前引入持久影响。
- `ROBOT_LOG_DIR` 位于 `/tmp`，运行产物不提交到 Git。

验证标准：

- `robot_env.sh` 语法正确。
- 加载后两个项目环境变量均显示预期值。
- 现有系统命令仍能正常使用。
- 只写 `day8_diagnostic_pipeline.sh` 时，Shell 能通过 `PATH` 找到它。
