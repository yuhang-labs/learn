二、find 组合筛选

任务 1：精确查找 Day4 日志

先进入学习目录：

```bash
cd ~/workspace/learn/learn
```

确认 Day4 日志仍然存在：

```bash
find robot-system-learning/linux -maxdepth 1 -type f -name '*.log' -printf '%f | %s bytes\n'
```

继续执行：

```bash
find robot-system-learning/linux -maxdepth 1 -type f -name '*.log' -printf '%f | %s bytes | %TY-%Tm-%Td %TH:%TM\n'

find robot-system-learning/linux -maxdepth 1 -type f -iname 'DAY4_CUSTOM.LOG' -printf '%f\n'

find robot-system-learning/linux -maxdepth 1 -type f -name '*.log' -size +500c -printf '%f | %s bytes\n'

find robot-system-learning/linux -maxdepth 1 -type f -name '*.log' -newermt '2 days ago' -printf '%f | %TY-%Tm-%Td %TH:%TM\n'
```

重点理解：

- 第一个位置参数是搜索起点。
- `-maxdepth 1` 表示最多检查起点目录和它的第一层内容，不递归进入更深目录。
- `-type f` 只保留普通文件。
- `-name` 区分大小写，`-iname` 不区分大小写。
- `-size +500c` 表示文件大小大于 500 字节，`c` 表示字节。
- `-newermt '2 days ago'` 根据修改时间筛选最近两天内修改的文件。
- 多个条件默认是“并且”关系，文件必须同时满足全部条件。
- `-printf` 自定义输出，`%f` 是文件名，`%s` 是字节数，`%T` 系列是修改时间。

验证标准：

- 能解释每条命令的搜索起点和筛选条件。
- 能说明 `-name` 与 `-iname` 的区别。
- 能说明为什么 `-size +500c` 不是“大于 500 KB”。
- 如果某条命令没有输出，要根据文件大小或修改时间判断这是正常无匹配还是命令错误。

三、find 与 grep 的组合

任务 2：使用 `-exec` 搜索日志内容

执行：

```bash
find robot-system-learning/linux -maxdepth 1 -type f -name '*.log' -exec grep -Hn -- 'Kernel' {} +
echo $?

find robot-system-learning/linux -maxdepth 1 -type f -name '*.log' -exec grep -Hn -- 'DAY5_NOT_FOUND' {} +
echo $?
```

重点理解：

- `-exec 命令 {} +` 把 `find` 找到的多个文件批量传给命令。
- `{}` 代表找到的文件路径。
- `+` 尽量一次传递多个文件，比每个文件执行一次更高效。
- `grep -Hn` 显示文件名和行号。
- `--` 表示后面的内容不再解析为选项，因此以 `-` 开头的关键字也能被当作普通文本。
- `find` 的退出状态主要表示遍历过程是否成功，不表示 `grep` 是否找到了内容。
- 因此第二组命令即使没有匹配，`find` 仍可能返回 `0`。不能据此写成“关键字匹配成功”。

验证标准：

- 第一组能够找到包含 `Kernel` 的日志行。
- 第二组没有匹配内容。
- 能解释为什么第二组的 `echo $?` 可能仍然是 `0`。
- 能说明项目脚本为什么需要直接保存 `grep` 的退出状态。

四、安全删除流程

任务 3：只在受控临时目录练习删除

本任务只允许操作 `/tmp/day5-delete-practice`，禁止把搜索起点改为 `/`、`/home` 或学习仓库。

执行：

```bash
practice_dir='/tmp/day5-delete-practice'
mkdir -p "$practice_dir"
touch "$practice_dir/keep.txt" "$practice_dir/remove.log"

find "$practice_dir" -maxdepth 1 -type f -printf '%f\n'

find "$practice_dir" -maxdepth 1 -type f -name '*.log' -print

find "$practice_dir" -maxdepth 1 -type f -name '*.log' -delete

find "$practice_dir" -maxdepth 1 -type f -printf '%f\n'
```

预期结果：

- 删除前同时存在 `keep.txt` 和 `remove.log`。
- 预览命令只显示 `remove.log`。
- 执行 `-delete` 后只剩 `keep.txt`。

重点理解：

- `-delete` 会直接删除匹配对象，不能撤销。
- 安全做法是先用完全相同的条件配合 `-print` 预览，再把最后的动作改为 `-delete`。
- 删除前必须再次确认搜索起点、`-type` 和名称条件。
- 本任务不要求清理 `/tmp/day5-delete-practice`，避免额外使用宽泛删除命令。

验证标准：

- 能说明为什么先预览比直接删除安全。
- 能指出本次删除的精确搜索起点、深度、类型和名称条件。
- `keep.txt` 必须保留。

五、项目实践：日志搜索工具

任务 4：编写 `day5_find_logs.sh`

创建文件：

```text
robot-system-learning/linux/day5_find_logs.sh
```

完整代码：

```bash
#!/bin/bash

search_dir="${1:-.}"
keyword="${2:-ERROR}"

if [ ! -d "$search_dir" ]; then
    echo "[ERROR] directory not found: $search_dir" >&2
    exit 2
fi

mapfile -d '' -t log_files < <(
    find "$search_dir" -maxdepth 2 -type f -name '*.log' -print0
)

if [ "${#log_files[@]}" -eq 0 ]; then
    echo "[INFO] no log files found in: $search_dir"
    exit 3
fi

echo "[INFO] searched log files: ${#log_files[@]}"

grep -Hn -- "$keyword" "${log_files[@]}"
grep_status=$?

case "$grep_status" in
    0)
        echo "[OK] keyword found: $keyword"
        exit 0
        ;;
    1)
        echo "[INFO] no matching line: $keyword"
        exit 1
        ;;
    *)
        echo "[ERROR] grep failed with status: $grep_status" >&2
        exit "$grep_status"
        ;;
esac
```

要求：

- 必须由用户自己创建脚本并逐段阅读。
- 不理解的语法先记录问题，不能直接写“已经理解”。
- 不要给脚本添加自动删除日志的功能；搜索工具和删除工具应分开。

六、理解脚本关键语法

任务 5：先阅读，再运行

重点理解：

- `${1:-.}`：未传第一个参数时，默认从当前目录搜索。
- `${2:-ERROR}`：未传第二个参数时，默认搜索 `ERROR`。
- `[ ! -d "$search_dir" ]`：判断搜索目录不存在。
- `mapfile`：把多条输入读取进 Bash 数组。
- `-print0`：使用空字符分隔文件路径，不使用换行符。
- `-d ''`：让 `mapfile` 按空字符读取。
- `-t`：去掉每项末尾的分隔符。
- `< <(...)`：进程替换，把括号中命令的输出提供给 `mapfile`。
- `${#log_files[@]}`：数组元素数量，也就是找到的日志文件数。
- `grep -Hn -- "$keyword" "${log_files[@]}"`：安全地把每个日志路径作为独立参数交给 `grep`。
- `grep` 返回 `0` 表示找到匹配，`1` 表示没有匹配，大于 `1` 表示执行错误。
- `case` 根据不同状态执行不同分支。

验证标准：

- 能解释为什么文件路径不能简单地按空格拆分。
- 能说明 `-print0` 与 `mapfile -d ''` 如何配合。
- 能说明数组元素数量是搜索的日志文件数量，不是匹配行数。
- 能说出脚本中退出状态 `0`、`1`、`2`、`3` 的意义。
