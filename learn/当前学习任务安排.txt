二、理解 USB 枚举与应用使用的关系

任务 1：建立整体概念

```text
USB 设备连接到主机控制器
            ↓
内核枚举设备并读取基本描述信息
            ↓
分配当前总线号和设备号，取得 VID:PID
            ↓
lsusb 展示当前枚举结果
            ↓
驱动、权限和应用功能还需要分别确认
```

重点理解：

- “枚举”表示主机已经发现 USB 设备并取得基本身份信息。
- `VID` 是厂商 ID，`PID` 是产品 ID，组合写成四位十六进制数，例如 `1234:5678`。
- Bus 和 Device 是本次连接中由系统分配的位置编号，设备重新连接后可能变化。
- 相同型号的多个设备通常具有相同 `VID:PID`，因此 `VID:PID` 不是每台物理设备唯一的序列号。
- `lsusb` 找到设备，只能证明枚举层面可见；它不能单独证明驱动正确、当前用户有访问权限或应用可以正常通信。

验证标准：

- 能按“连接 → 内核枚举 → `lsusb` 展示 → 继续确认驱动、权限和功能”的顺序解释。

三、确认工具并执行第一次枚举

任务 2：检查 `lsusb` 并保留真实结果

执行：

```bash
command -v lsusb
tool_status="$?"
printf 'lsusb tool status=%s\n' "$tool_status"

lsusb --version

lsusb
enumerate_status="$?"
printf 'lsusb enumerate status=%s\n' "$enumerate_status"
```

结果判断：

- `command -v` 输出路径且 `tool_status=0`，表示命令已安装。
- `lsusb` 输出若干 `Bus ... Device ... ID ...` 行且状态为 `0`，进入“实际枚举路径”。
- 如果 `lsusb` 返回 `unable to initialize libusb`、权限错误或其他非 0 状态，进入“受限环境路径”。
- 如果 `tool_status` 非 0，不继续执行后面的实机 USB 查询，也不自行安装软件；保留错误并说明需要教师处理环境。

重点理解：

- 命令存在只证明工具已安装，不代表当前运行环境允许它访问 USB 枚举信息。
- 枚举失败是环境证据，不能据此断言电脑没有 USB 设备。

验证标准：

- 保留工具路径、版本、`lsusb` 原始输出或原始错误，以及对应状态。

四、读取 lsusb 列表字段

任务 3：实际枚举成功时，选择一行识别字段

`lsusb` 的常见行格式：

```text
Bus 001 Device 004: ID 1234:5678 Vendor Product
```

字段含义：

- `Bus 001`：当前 USB 总线号。
- `Device 004`：设备在该总线上的当前设备号。
- `ID 1234:5678`：`VID:PID`，用于识别厂商和产品型号。
- 最后的文字：usbutils 数据库提供的厂商或产品描述；可能完整、简略或缺失。

如果任务 2 枚举成功，从你自己的输出中选择一行，并记录：

```text
选择的完整行：
Bus：
Device：
VID:PID：
描述：
```

不要记录 `lsusb -v` 输出，不要寻找或记录序列号。

验证标准：

- 能从一行真实输出中准确指出四类信息。
- 不把 Bus/Device 编号误认为稳定设备身份。

五、查看 USB 连接层级

任务 4：实际枚举成功时查看树形结果

执行：

```bash
lsusb -t
tree_status="$?"
printf 'lsusb tree status=%s\n' "$tree_status"
```

常见字段：

- `Bus`、`Port`、`Dev`：当前连接层级和位置。
- `Class`：设备或接口类别，例如 Hub、Human Interface Device。
- `Driver`：当前绑定的内核驱动；显示为空或 `(none)` 时，需要后续继续定位。
- `12M`、`480M`、`5000M` 等：该连接显示的速率。

重点理解：

- `lsusb` 默认输出偏向“有哪些设备和它们的 ID”。
- `lsusb -t` 偏向“设备接在哪一层、属于什么类别、绑定什么驱动、显示什么速率”。
- 树中出现驱动仍不等于应用功能一定正常。

验证标准：

- 保留完整树形输出，并从中选择一项指出其 Class、Driver 和速率。

七、按 VID:PID 过滤真实设备

任务 6：仅在实际枚举成功时执行

把下面的 `1234:5678` 替换为任务 3 中真实设备的 `VID:PID`，不要照抄示例值：

```bash
usb_id='1234:5678'
lsusb -d "$usb_id"
filter_status="$?"
printf 'selected USB filter status=%s\n' "$filter_status"
```

然后验证一个格式正确但预期没有匹配的 ID：

```bash
lsusb -d 0000:0000
no_match_status="$?"
printf 'USB no-match status=%s\n' "$no_match_status"
```

最后验证格式错误：

```bash
lsusb -d not-an-id
invalid_id_status="$?"
printf 'invalid USB ID status=%s\n' "$invalid_id_status"
```

预期：

- 真实 `VID:PID` 过滤后只显示对应型号的已枚举设备，状态为 `0`。
- `0000:0000` 通常没有匹配输出，状态为非 0；如果你的环境意外出现匹配，保留真实结果并说明。
- `not-an-id` 会被识别为输入格式错误，显示帮助或错误，状态为非 0。

重点理解：

- “没有匹配设备”表示当前枚举列表中找不到该 `VID:PID`。
- “格式错误”表示命令无法把输入解析为合法 `VID:PID`。
- 两者都可能返回非 0，但失败阶段不同。

验证标准：

- 保留真实匹配、没有匹配和格式错误三项结果及状态。

八、创建 USB 枚举检查脚本

任务 7：创建 `usb_device_check.sh`

执行：

```bash
cd "$HOME/workspace/learn/learn/robot-system-learning/linux"
vim usb_device_check.sh
```

在 Vim 中写入下面的完整内容：

```bash
#!/bin/bash

usb_id="$1"

if [[ -z "$usb_id" ]]; then
    printf '%s\n' '[USB CHECK ERROR] VID:PID is required' >&2
    exit 1
fi

if [[ ! "$usb_id" =~ ^[[:xdigit:]]{4}:[[:xdigit:]]{4}$ ]]; then
    printf '[USB CHECK ERROR] invalid VID:PID: %s\n' "$usb_id" >&2
    exit 1
fi

usb_output="$(lsusb 2>&1)"
enumerate_status="$?"

if [[ "$enumerate_status" -ne 0 ]]; then
    printf '%s\n' '[USB CHECK ERROR] USB enumeration failed' >&2
    printf '%s\n' "$usb_output" >&2
    exit 2
fi

match_output="$(printf '%s\n' "$usb_output" | grep -i -F "ID $usb_id ")"

if [[ -z "$match_output" ]]; then
    printf '[USB CHECK ERROR] no enumerated device matched: %s\n' \
        "$usb_id" >&2
    exit 1
fi

printf '[USB FOUND] VID:PID=%s\n' "$usb_id"
printf '%s\n' "$match_output"
```

保存后执行：

```bash
bash -n usb_device_check.sh
chmod u+x usb_device_check.sh
ls -l usb_device_check.sh
cat usb_device_check.sh
```

脚本整体逻辑：

1. 检查是否提供 `VID:PID`。
2. 检查输入是否为 `四位十六进制:四位十六进制`。
3. 执行一次 `lsusb`，枚举环境失败时保留原始错误并返回状态 `2`。
4. 枚举成功后，按 `VID:PID` 查找匹配行。
5. 找到时输出 `[USB FOUND]`；没有匹配时返回状态 `1`。

验证标准：

- `bash -n` 没有输出。
- owner 具有执行权限。
- 脚本内容与上面的完整版本一致。

预期：

- 没有匹配的合法 ID 输出 no enumerated device matched，状态为 `1`。
- 格式错误和空输入均在执行 `lsusb` 前被拒绝，状态为 `1`。

如果任务 2 的实际枚举失败，则执行：

```bash

environment_status="$?"
printf 'USB environment status=%s\n' "$environment_status"
```

预期：

- 脚本输出 USB enumeration failed 和原始 `lsusb` 错误，状态为 `2`。
- 这证明脚本没有把“环境无法枚举”误报成“设备没有匹配”。

验证标准：

- 无效输入分支正确。
- 枚举成功环境完成“找到”和“未找到”分支；受限环境完成“枚举失败”分支。
