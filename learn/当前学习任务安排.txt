二、理解接口、路由与 ping 的关系

任务 1：建立整体概念

```text
Day18：接口存在并配置地址
             ↓
ip route get：为目标地址选择发送接口和源地址
             ↓
ping：发送有限次数的 ICMP Echo 请求
             ↓
收到应答后统计接收数量、丢包率和往返时间
```

重点理解：

- 网络接口是发送和接收数据的对象，路由决定数据应从哪个接口方向发送。
- `ip route get` 查询内核对一个具体目标的路由选择，不发送 ping 数据包。
- `ping` 在路由选择基础上尝试 IP 层往返，并统计是否收到 ICMP Echo Reply。
- 路由查询成功只说明系统找到了发送决策，不保证目标一定应答。
- ping 成功说明目标对本次 ICMP 请求有应答，不保证 SSH、ROS2 或其他应用服务正常。
- ping 失败也不能单独证明目标主机已关机，可能是名称无效、没有路由、丢包或 ICMP 被限制。

验证标准：

- 后续能按“接口与地址 → 路由选择 → ping 往返 → 结果边界”的顺序解释实验。

四、查询回环目标的路由

任务 3：使用 ip route get 查询单个安全目标

执行：

```bash
ip route get 127.0.0.1
```

预期：

- 输出包含目标 `127.0.0.1`。
- 输出包含接口 `dev lo`。
- 输出中的源地址应为回环地址 `src 127.0.0.1`。
- 常见结果会包含 `local`，表示目标属于本机。

重点理解：

- `get` 是询问“如果发送到这个目标，内核会怎样选择”，不是修改路由。
- `dev lo` 表示该目标通过回环接口处理。
- `src 127.0.0.1` 表示系统为这次路由选择的源地址。
- 本次只查询单个回环目标，不记录完整路由表。

验证标准：

- 保留完整输出，并指出目标、`dev lo` 和 `src 127.0.0.1`。

五、使用 ping 验证本机往返

任务 4：向回环地址发送有限次数的请求

执行：

```bash
ping -c 3 -W 1 127.0.0.1
ping_status="$?"
printf 'loopback ping status=%s\n' "$ping_status"
```

预期：

- 输出 3 条来自 `127.0.0.1` 的应答。
- 统计中 transmitted 与 received 都为 3，packet loss 为 `0%`。
- 输出往返时间统计。
- `ping_status=0`。

重点理解：

- `-c 3` 让 ping 在发送 3 次后自动结束。
- `-W 1` 限制单次等待应答的时间。
- `icmp_seq` 表示请求序号，`time` 表示该次往返耗时。
- 汇总中的 transmitted、received 和 packet loss 比单独一行应答更适合判断整体结果。
- 回环 ping 成功只验证本机 IP 栈的这条路径，不证明外部网络可达。

验证标准：

- 保留三次应答、汇总统计和状态 `0`。

- 不要为了消除错误而修改系统路由。

验证标准：

八、创建路由与 ping 检查脚本

任务 7：为 Robot System Diagnostic Tool 创建项目脚本

执行：

```bash
cd "$HOME/workspace/learn/learn/robot-system-learning/linux"
vim route_ping_check.sh
```

在 Vim 中写入下面的完整内容：

```bash
#!/bin/bash

target="$1"

if [[ -z "$target" ]]; then
    printf '%s\n' '[ROUTE PING ERROR] target IPv4 address is required' >&2
    exit 1
fi

printf '[ROUTE CHECK] target=%s\n' "$target"
route_output="$(ip route get "$target" 2>&1)"
route_status="$?"

if (( route_status != 0 )); then
    printf '%s\n' "$route_output" >&2
    printf '[ROUTE PING ERROR] route lookup failed; target=%s\n' "$target" >&2
    exit "$route_status"
fi

printf '%s\n' "$route_output"
printf '[PING CHECK] target=%s\n' "$target"
ping -c 3 -W 1 "$target"
ping_status="$?"

if (( ping_status != 0 )); then
    printf '[ROUTE PING ERROR] ping failed; target=%s status=%s\n' \
        "$target" "$ping_status" >&2
    exit "$ping_status"
fi

printf '[ROUTE PING COMPLETE] target=%s\n' "$target"
```

保存后执行：

```bash
bash -n route_ping_check.sh
chmod u+x route_ping_check.sh
ls -l route_ping_check.sh
cat route_ping_check.sh
```

脚本整体逻辑：

1. 接收一个目标 IPv4 地址。
2. 没有输入时输出错误并停止。
3. 使用 `ip route get` 查询该目标的路由选择。
4. 路由查询失败时保留原始错误并停止，不继续 ping。
5. 路由查询成功后执行 3 次有限等待的 ping。
6. ping 失败时输出目标和状态，成功时输出完成提示。

重点理解：

- 脚本先查路由，再做往返验证，顺序对应网络诊断层次。
- 脚本只读取路由和发送有限测试请求，不修改网络配置。
- 原始路由错误被保留，便于区分输入错误与 ping 失败。
- 本日只理解脚本整体流程，不要求掌握命令替换或状态码语法。

验证标准：

- `bash -n` 没有输出，表示没有发现 Shell 语法错误。
- 权限中 owner 具有 `x`。
- 文件内容与上面的完整脚本一致。
