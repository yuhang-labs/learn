二、确认当前用户和所属组

任务 1：获取“谁正在执行命令”的证据

执行：

```bash
whoami
id
groups
```

重点观察：

- `whoami` 显示当前有效用户名。
- `id` 同时显示用户 ID、主组和附加组。
- `groups` 直接列出当前用户所属的组。

整体逻辑：

```text
当前 Shell 中的进程
        ↓
携带当前用户身份和所属组
        ↓
访问文件时，用这些身份信息与文件的 owner/group 比较
```

重点理解：

- 用户表示一个操作身份，组用于把多个用户归入同一个权限集合。
- 组名不是文件夹名；它是访问控制中的身份信息。
- 不要求记住数字 UID 或 GID，只需能从输出中找到用户名和组名。

验证标准：

- 保留三个命令的真实输出。
- 能指出当前用户名、主组以及当前用户所属的组。

三、查看测试目录和文件的权限归属

任务 2：在 `/tmp` 创建只属于本次练习的测试对象

执行：

```bash
practice_dir='/tmp/day12-permission-practice'
mkdir -p "$practice_dir"
printf '%s\n' 'robot status: ready' > "$practice_dir/status.txt"

chmod u=rwx,go= "$practice_dir"
chmod u=rw,go= "$practice_dir/status.txt"

ls -ld "$practice_dir"
ls -l "$practice_dir/status.txt"
stat -c 'permissions=%A | owner=%U | group=%G | file=%n' "$practice_dir" "$practice_dir/status.txt"
```

预期：

- 目录和文件的 owner 是当前用户。
- 目录的 owner 具有读、写、进入权限，group 和 other 没有权限。
- 文件的 owner 具有读、写权限，group 和 other 没有权限。
- `stat` 将权限、所有者、所属组和路径显示在同一行，方便对照。

如何阅读 `ls -l` 的权限部分：

```text
- rw- --- ---
│  │   │   └─ other：其他用户
│  │   └───── group：文件所属组
│  └───────── owner：文件所有者
└──────────── 文件类型；“-”表示普通文件，“d”表示目录
```

重点理解：

- owner、group、other 是三类访问身份，不是三个同时叠加的权限包。
- 当前进程访问文件时，系统先根据身份判断应使用哪一组权限，再检查该组是否允许本次操作。
- 文件名存在只证明目录中有这个对象，不证明当前身份一定能读取它。
- 这里使用符号形式的 `chmod` 只是为了建立明确测试状态，不要求记忆写法。

验证标准：

- 保留 `ls -ld`、`ls -l` 和 `stat` 的真实输出。
- 能从输出中指出文件类型、owner、group，以及三组权限的位置。

四、验证正常读取

任务 3：在 owner 具有读权限时读取文件

执行：

```bash
cat "$practice_dir/status.txt"
```

预期：

```text
robot status: ready
```

判断过程：

1. 当前用户与文件 owner 相同。
2. 因此本次访问使用 owner 权限。
3. owner 权限中有 `r`。
4. `cat` 可以读取文件内容。

验证标准：

- 保留正常读取结果。
- 能根据身份匹配和 owner 权限解释为什么读取成功。

五、安全复现权限拒绝并恢复

任务 4：只修改临时文件，观察同一个用户失去读权限后的结果

执行：

```bash
chmod u-r "$practice_dir/status.txt"
ls -l "$practice_dir/status.txt"
cat "$practice_dir/status.txt"
```

预期：

- `ls -l` 显示 owner 的读权限已经消失。
- `cat` 提示“权限不够”或 `Permission denied`。
- 这次失败是实验预期，不代表命令输错。

随后立即恢复并回归验证：

```bash
chmod u+r "$practice_dir/status.txt"
ls -l "$practice_dir/status.txt"
cat "$practice_dir/status.txt"
```

预期：

- owner 的读权限恢复。
- `cat` 再次显示 `robot status: ready`。

整体逻辑：

```text
同一当前用户 + 同一文件
          ↓
只移除 owner 的读取权限
          ↓
读取失败
          ↓
恢复 owner 的读取权限
          ↓
读取成功
```

重点理解：

- 这个最小实验只改变一个条件，因此可以证明失败与 owner 的读权限有关。
- 系统不会因为 group 或 other 可能有权限，就把 owner 自动改当成另一类身份；身份匹配后使用对应的权限组。
- 不需要记忆错误状态码，读懂错误文字并用权限证据定位即可。

验证标准：

- 同时保留拒绝访问和恢复后成功访问的真实输出。
- 能说明实验中唯一改变的条件是什么。

六、权限问题的诊断顺序

任务 5：根据证据逐层判断，不直接猜测

出现“权限不够”时，按下面顺序执行和思考：

```bash
whoami
id
ls -ld "$practice_dir"
ls -l "$practice_dir/status.txt"
stat -c 'permissions=%A | owner=%U | group=%G | file=%n' "$practice_dir" "$practice_dir/status.txt"
```

诊断顺序：

1. 确认当前用户和所属组。
2. 确认路径中的目录及目标文件真实存在。
3. 查看目录和文件的 owner、group 与权限。
4. 判断当前身份匹配 owner、group 还是 other。
5. 检查匹配到的权限组是否允许所需操作。
6. 只在明确根因后，针对测试对象做最小修改并重新验证。

重点理解：

- `ls -l` 能证明文件当前的权限、所有者和所属组，但不能单独证明“当前进程是谁”，所以还需要 `whoami` 或 `id`。
- 目录权限也会影响能否通过路径访问文件，因此排查时不能只看目标文件。
- 今天只建立诊断思路，不展开目录权限的每种组合。

验证标准：

- 保留诊断命令的真实输出。
- 能按身份、路径、归属、匹配权限、回归验证的顺序说明排查过程。
