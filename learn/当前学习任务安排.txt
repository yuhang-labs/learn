二、Linux 文件信息

任务 1：查看文件类型与元数据

先进入学习目录：

```bash
cd ~/workspace/learn/learn
```

执行：

```bash
file robot-system-learning/linux/day3_args.sh
stat robot-system-learning/linux/day3_args.sh
stat -c '名称=%n 类型=%F 大小=%s 权限=%A 所有者=%U:%G inode=%i' robot-system-learning/linux/day3_args.sh
```

重点理解：

- `file` 根据文件内容判断文件类型。
- `stat` 显示文件大小、权限、所有者、时间和 inode 等元数据。
- inode 是文件在文件系统中的标识，不等于文件名。

验证标准：

- 能说明 `file` 和 `stat` 的区别。
- 能在 `stat` 输出中找到大小、权限、所有者、修改时间和 inode。
- 在 out.md 中写出自己的解释，不能只粘贴输出。

三、Linux 系统与资源状态

任务 2：查看系统身份

执行：

```bash
uname -r
uname -m
hostname
cat /etc/os-release
```

重点理解：

- `uname -r` 显示 Linux 内核版本。
- `uname -m` 显示硬件架构，例如 x86_64 或 aarch64。
- `hostname` 显示主机名。
- `/etc/os-release` 保存 Ubuntu 等发行版的信息。

验证标准：

- 能说出自己的内核版本、硬件架构、主机名和发行版。
- 能解释 Linux 内核与 Ubuntu 发行版不是同一个概念。

任务 3：查看磁盘、内存和负载

执行：

```bash
df -h /
du -sh robot-system-learning
free -h
uptime
```

重点理解：

- `df` 查看文件系统整体容量和剩余空间。
- `du` 统计指定文件或目录占用的空间。
- `free` 查看物理内存和交换空间。
- `uptime` 显示开机时长、登录用户数和平均负载。
- `uptime` 的三个负载值不是 CPU 使用百分比，分别表示过去 1、5、15 分钟的平均负载。

验证标准：

- 能说明 `df` 与 `du` 的区别。
- 能在 `free -h` 中找到 total、used、available。
- 能指出 `uptime` 中哪个是 1 分钟、5 分钟、15 分钟负载。

四、Shell 退出状态与命令检测

任务 4：理解 `$?` 和 `command -v`

以下命令必须逐组执行。`echo $?` 必须紧跟在被检查的命令后：

```bash
true
echo $?

false
echo $?

command -v uname
echo $?

command -v day4_missing_command
echo $?
```

重点理解：

- `$?` 保存上一条命令的退出状态。
- 退出状态 `0` 表示成功，非 `0` 表示失败。
- `command -v 命令名` 用于检查 Shell 能否找到该命令。
- 如果在目标命令和 `echo $?` 之间执行了其他命令，`$?` 就会变成其他命令的退出状态。

验证标准：

- `true` 后的退出状态是 `0`。
- `false` 后的退出状态不是 `0`。
- `command -v uname` 能输出路径或命令信息。
- 不存在的命令没有路径，退出状态不是 `0`。

五、项目实践：Robot System Diagnostic Tool v0.1

任务 5：编写完整诊断脚本

创建文件：

```text
robot-system-learning/linux/day4_system_check.sh
```

完整代码：

```bash
#!/bin/bash

output_file="${1:-day4_system_check.log}"
required_commands=(date uname hostname df free uptime)

check_command() {
    local command_name="$1"

    if command -v "$command_name" >/dev/null 2>&1; then
        echo "[OK] $command_name"
        return 0
    fi

    echo "[ERROR] missing command: $command_name" >&2
    return 1
}

if [ "${DAY4_TEST_MISSING:-0}" = "1" ]; then
    required_commands+=(day4_missing_command)
fi

for command_name in "${required_commands[@]}"; do
    check_command "$command_name" || exit 1
done

{
    echo "=== Robot System Diagnostic ==="
    echo "Time: $(date '+%F %T')"
    echo "Host: $(hostname)"
    echo "Kernel: $(uname -r)"
    echo "Architecture: $(uname -m)"
    echo
    echo "--- Root Filesystem ---"
    df -h /
    echo
    echo "--- Memory ---"
    free -h
    echo
    echo "--- Uptime And Load ---"
    uptime
} > "$output_file" 2>&1

echo "Report saved to: $output_file"
```

要求：

- 必须由用户自己创建并检查脚本内容。
- 不理解的代码先记录问题，不要直接写“已经理解”。
- 日志文件是运行产物，不提交到 Git。

任务 6：正常场景验证

执行：

```bash
chmod +x robot-system-learning/linux/day4_system_check.sh
cd robot-system-learning/linux
./day4_system_check.sh
echo $?
cat day4_system_check.log

./day4_system_check.sh day4_custom.log
echo $?
cat day4_custom.log
```

验证标准：

- 每次运行都输出 6 个 `[OK]`。
- 两次正常运行的退出状态都是 `0`。
- 默认日志和自定义日志都成功生成。
- 日志包含时间、主机名、内核、架构、磁盘、内存和负载。

任务 7：异常场景验证

在 `robot-system-learning/linux` 目录执行：

```bash
DAY4_TEST_MISSING=1 ./day4_system_check.sh day4_failed.log
echo $?
test -e day4_failed.log
echo $?
```

预期结果：

- 前 6 个真实命令显示 `[OK]`。
- `day4_missing_command` 显示 `[ERROR]`。
- 脚本退出状态不是 `0`。
- `day4_failed.log` 不应生成，因为脚本在写报告前已经停止。
- `test -e day4_failed.log` 的退出状态应为非 `0`。

验证标准：

- 能说明为什么缺少必要命令时脚本停止。
- 能说明错误信息为什么使用 `>&2`。
- 能说明异常测试为什么不能只看屏幕文字，还要检查退出状态和文件是否生成。
