二、理解 kill 与 signal

任务 1：建立整体概念

```text
发送方进程
    ↓ 使用 kill/pkill
向目标进程发送 signal
    ↓
目标进程根据 signal 继续、清理或结束
```

重点理解：

- `kill` 的核心动作是向进程发送信号，不等于无条件强制结束。
- 本次使用的 `TERM` 表示“请求结束”，目标程序可以在退出前清理。
- 发送命令没有报错，只能证明请求被系统接受；还要检查目标进程和清理输出。
- `kill` 按明确 PID 定位实例；`pkill` 按名称或模式匹配，可能同时影响多个进程。
- 执行 `pkill` 前必须先查看完全相同模式的匹配范围。

验证标准：

- 后续实验同时保留发送前、发送后和回归查询证据。

三、创建能处理 TERM 的临时 worker

任务 2：在 `/tmp` 创建信号实验 worker

执行：

```bash
practice_dir='/tmp/day15-signal-practice'
worker_script="$practice_dir/day15_worker.sh"
worker_log="$practice_dir/day15_worker.log"

mkdir -p "$practice_dir"
vim "$worker_script"
```

在 Vim 中写入下面的完整内容：

```bash
#!/bin/bash

trap 'printf "%s\n" "[WORKER] TERM received; cleanup complete"; exit 0' TERM

printf '[WORKER] ready pid=%s\n' "$$"

while true; do
    sleep 1
done
```

保存后执行：

```bash
bash -n "$worker_script"
chmod u+x "$worker_script"
cat "$worker_script"
```

重点理解：

- `trap` 让 worker 收到 `TERM` 时先输出清理信息，再退出。
- 循环只是让临时 worker 保持运行，不要求学习代码细节。
- worker 和日志位于 `/tmp`，不提交到 Git。

验证标准：

- 文件内容正确，`bash -n` 没有语法错误。

四、按 PID 发送 TERM

任务 3：启动 worker，确认目标后请求其正常结束

启动并获取证据：

```bash
: > "$worker_log"
"$worker_script" > "$worker_log" 2>&1 &
worker_pid="$!"

sleep 1

printf 'worker PID: %s\n' "$worker_pid"
ps -p "$worker_pid" -o pid,ppid,user,stat,etime,cmd
cat "$worker_log"
```

预期：

- `ps` 显示的 PID 与 `worker_pid` 一致。
- worker 由当前用户运行。
- 日志显示 `[WORKER] ready pid=...`，其中 PID 与目标一致。

确认无误后执行：

```bash
kill -TERM "$worker_pid"
wait "$worker_pid"

cat "$worker_log"
ps -p "$worker_pid" -o pid,ppid,user,stat,etime,cmd ||
  printf '%s\n' '[EXPECTED] worker stopped after TERM'
```

预期：

- 日志新增 `[WORKER] TERM received; cleanup complete`。
- 最终 `ps` 不再显示该 worker。
- 清理文字证明 worker 收到并处理了 `TERM`。

整体流程：

```text
启动 worker → 记录 PID → ps 与日志确认目标
                           ↓
                    kill 发送 TERM
                           ↓
                 worker 执行清理并退出
                           ↓
                查看日志并重新查询 PID
```

验证标准：

- 保留发送前的目标证据、清理日志和发送后的查询结果。

五、安全验证不存在的目标

任务 4：只对确定不可能存在的 PID 复现错误

执行：

```bash
invalid_pid='99999999'

ps -p "$invalid_pid" -o pid,ppid,user,stat,etime,cmd ||
  printf '%s\n' '[EXPECTED] invalid PID is not running'

kill -TERM "$invalid_pid"
```

预期：

- 查询先确认 PID `99999999` 不存在。
- `kill` 提示“没有那个进程”或 `No such process`。

重点理解：

- 异常测试也必须先确认目标，不能随意使用可能属于其他进程的 PID。
- 不重新使用旧 PID，因为数字可能被复用。
- 读懂错误文字即可，不要求记忆状态码。

验证标准：

- 保留发送前的无目标证据和 `kill` 错误文字。

六、使用 pkill 处理唯一名称的临时进程

任务 5：创建两个同名临时 worker，观察名称匹配范围

请将下面整段命令一次执行，不修改匹配模式：

```bash
bash -c 'exec -a day15-pkill-worker sleep 60' &
pkill_pid_one="$!"

bash -c 'exec -a day15-pkill-worker sleep 60' &
pkill_pid_two="$!"

sleep 1

printf 'worker one PID: %s\n' "$pkill_pid_one"
printf 'worker two PID: %s\n' "$pkill_pid_two"

printf '%s\n' '[BEFORE] exact name matches'
pgrep -af '^day15-pkill-worker '

pkill -TERM -f '^day15-pkill-worker '

wait "$pkill_pid_one" 2>/dev/null || true
wait "$pkill_pid_two" 2>/dev/null || true

printf '%s\n' '[AFTER] exact name matches'
pgrep -af '^day15-pkill-worker ' ||
  printf '%s\n' '[EXPECTED] no day15 pkill workers remain'
```

预期：

- 发送前显示两个不同 PID。
- 精确模式只匹配两个本次创建的临时进程。
- 发送后不再显示这两个进程。

重点理解：

- `kill` 使用 PID 指向一个明确实例。
- `pkill` 根据名称或命令行模式选择目标，一次可能匹配多个实例。
- 名称模式过宽可能影响无关进程，必须先用相同模式查看结果。
- 禁止将本次模式改成宽泛的 `sleep`、`bash` 或 `robot`。

验证标准：

- 保留发送前两个 PID 和发送后无匹配的证据。

七、项目实践：创建 process_check.sh

任务 6：为 Robot System Diagnostic Tool 创建 PID 检查脚本

执行：

```bash
cd "$HOME/workspace/learn/learn/robot-system-learning/linux"
vim process_check.sh
```

在 Vim 中写入下面的完整内容：

```bash
#!/bin/bash

target_pid="$1"

if [[ -z "$target_pid" ]]; then
    printf '%s\n' '[PROCESS CHECK ERROR] PID is required' >&2
    exit 1
fi

if [[ ! "$target_pid" =~ ^[0-9]+$ ]]; then
    printf '[PROCESS CHECK ERROR] invalid PID: %s\n' "$target_pid" >&2
    exit 1
fi

if kill -0 "$target_pid" 2>/dev/null; then
    printf '[PROCESS RUNNING] PID=%s\n' "$target_pid"
    ps -p "$target_pid" -o pid,ppid,user,stat,etime,cmd
else
    printf '[PROCESS NOT RUNNING OR NOT ACCESSIBLE] PID=%s\n' "$target_pid"
    exit 1
fi
```

保存后执行：

```bash
bash -n process_check.sh
chmod u+x process_check.sh
ls -l process_check.sh
```

脚本整体逻辑：

1. 接收一个 PID。
2. 检查 PID 是否为空或格式无效。
3. 使用 `kill -0` 检查目标是否存在且当前用户可访问，不发送终止信号。
4. 可访问时输出运行状态和 `ps` 证据。
5. 不存在或不可访问时输出明确提示。

重点理解：

- `kill -0` 不会结束进程，只做存在性和权限检查。
- 检查失败可能表示进程不存在，也可能表示当前用户无权访问。
- 只需理解输入、检查和输出证据的整体框架，不要求记住代码语法。

验证标准：

- 脚本语法通过并具有 owner 执行权限。
- 文件位于 `robot-system-learning/linux/process_check.sh`。
