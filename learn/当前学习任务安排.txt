二、理解 socket、TCP、UDP 与 ss

任务 1：建立整体概念

```text
应用程序创建 socket 并绑定本机地址和端口
                    ↓
TCP socket 等待连接时显示 LISTEN
UDP socket 等待数据报时通常显示 UNCONN
                    ↓
ss 从内核读取并展示当前 socket 状态
                    ↓
按协议和端口过滤后形成诊断证据
```

重点理解：

- socket 是程序使用网络协议栈进行通信的端点，通常与协议、本地地址和端口相关。
- TCP 在通信前建立连接，监听 socket 等待连接时显示 `LISTEN`。
- UDP 不建立 TCP 式连接，绑定后的 socket 通常显示 `UNCONN`。
- `ss` 只展示查询时刻的 socket 状态，不会因为查看而创建或关闭 socket。
- TCP `38080` 与 UDP `38080` 是不同的协议端点，端口号相同也不能忽略协议。
- socket 存在只证明某个程序绑定或监听了端口，不保证应用的完整业务功能正常。

验证标准：

- 后续能按“程序创建 socket → 内核保存状态 → ss 按协议和端口查询”的顺序解释实验。

四、创建 socket 检查脚本

任务 3：为 Robot System Diagnostic Tool 创建项目脚本

执行：

```bash
cd "$HOME/workspace/learn/learn/robot-system-learning/linux"
vim socket_listener_check.sh
```

在 Vim 中写入下面的完整内容：

```bash
#!/bin/bash

protocol="$1"
port="$2"

if [[ -z "$protocol" || -z "$port" ]]; then
    printf '%s\n' '[SOCKET CHECK ERROR] protocol and port are required' >&2
    exit 1
fi

if [[ ! "$port" =~ ^[0-9]+$ ]] || (( port < 1 || port > 65535 )); then
    printf '[SOCKET CHECK ERROR] invalid port: %s\n' "$port" >&2
    exit 1
fi

case "$protocol" in
    tcp)
        socket_output="$(ss -H -lnt "sport = :$port" 2>&1)"
        ss_status="$?"
        ;;
    udp)
        socket_output="$(ss -H -lnu "sport = :$port" 2>&1)"
        ss_status="$?"
        ;;
    *)
        printf '[SOCKET CHECK ERROR] unsupported protocol: %s\n' "$protocol" >&2
        exit 1
        ;;
esac

if (( ss_status != 0 )); then
    printf '%s\n' "$socket_output" >&2
    printf '[SOCKET CHECK ERROR] ss query failed; protocol=%s port=%s\n' \
        "$protocol" "$port" >&2
    exit "$ss_status"
fi

if [[ -z "$socket_output" ]]; then
    printf '[SOCKET CHECK ERROR] no matching socket; protocol=%s port=%s\n' \
        "$protocol" "$port" >&2
    exit 1
fi

printf '[SOCKET FOUND] protocol=%s port=%s\n' "$protocol" "$port"
printf '%s\n' "$socket_output"
```

保存后执行：

```bash
bash -n socket_listener_check.sh
chmod u+x socket_listener_check.sh
ls -l socket_listener_check.sh
cat socket_listener_check.sh
```

脚本整体逻辑：

1. 接收协议和端口两个输入。
2. 缺少输入或端口范围无效时输出错误并停止。
3. 根据 `tcp` 或 `udp` 选择对应的 ss 查询。
4. 不支持的协议会被拒绝。
5. ss 查询失败时保留原始错误。
6. 查询成功但没有匹配 socket 时输出 no matching socket。
7. 找到匹配项时输出协议、端口和经过过滤的 socket 状态。

重点理解：

- 脚本只读取 socket 状态，不创建、关闭或修改任何 socket。
- 端口先限制为 `1～65535` 的数字，避免把无效内容交给 ss 过滤器。
- TCP 和 UDP 使用不同查询，避免只看端口号造成误判。
- 本日只理解整体分支和输出，不要求掌握正则、case 或命令替换语法。

验证标准：

- `bash -n` 没有输出，表示没有发现 Shell 语法错误。
- 权限中 owner 具有 `x`。
- 文件内容与上面的完整脚本一致。

六、创建受控 TCP 与 UDP socket

任务 5：启动最长 5 分钟的本机临时进程

请将下面整段命令一次执行：

```bash
python3 -c '
import socket
import time

tcp_socket = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
tcp_socket.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
tcp_socket.bind(("127.0.0.1", 38080))
tcp_socket.listen()

udp_socket = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
udp_socket.bind(("127.0.0.1", 38081))
```

结果判断：

- `ps` 找到进程后立即继续后面的检查。
- 如果 Python 报地址已被使用或 `ps` 找不到进程，保留错误并停止，不启动其他端口或修改系统服务。

任务 8：交叉使用错误协议查询
